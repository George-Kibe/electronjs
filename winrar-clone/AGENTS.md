# AGENTS.md — WinrarClone

The root [`AGENTS.md`](../AGENTS.md) also applies to this project. The rules here are more specific.

## Map

```
winrar-clone/app/
├── src/main/
│   ├── engine/        # 7-Zip adapter: binary resolution, argument building, output parsers, process control
│   ├── jobs/          # JobManager: queue, concurrency, progress, cancellation, staging & finalize
│   ├── safety/        # path validation, symlink policy, bomb guard, MotW, free-space checks
│   ├── integration/   # CLI args parsing, single-instance forwarding, file associations, context menu (un)registration
│   ├── ipc/           # typed, zod-validated handlers
│   └── services/      # settings, recent files, updates, notifications, temp-dir janitor
├── src/preload/       # contextBridge `window.api`
├── src/renderer/      # React UI (no Node access)
├── src/shared/        # IPC contract types + zod schemas
├── scripts/           # fetch-7zip.ts (pinned versions + SHA-256), make-fixtures.ts
├── build/             # NSIS includes (registry context menu), entitlements, Linux .desktop templates
├── test/fixtures/     # generated archive corpus (incl. malicious samples) — see docs/07
└── e2e/
```

## Commands (inside `winrar-clone/app`)

`pnpm dev` · `pnpm lint` · `pnpm typecheck` · `pnpm test` · `pnpm test:e2e` · `pnpm fixtures` (regenerate corpus) · `pnpm dist`

## Architecture rules

1. **All 7-Zip calls go through `engine/`.** Build argument arrays (never shell strings). Use `spawn` with
   `shell: false`. Always pass `--` before archive and file paths so a filename that starts with `-` is not
   parsed as a switch.
2. **All extractions go through `jobs/` + `safety/`:** list first → validate → extract into a staging dir on
   the same volume → post-validate → move into place. Never extract directly into the user's destination.
3. The renderer never receives absolute paths it did not get from a user action (dialog, drop, CLI). Main
   keeps a map of allowed roots per job.
4. Output parsers must be pure functions with fixture-based tests (captured 7-Zip output per OS and version).
5. Passwords never hit logs, argv of long-lived processes, crash reports or settings (see docs/06 §5).
6. When you bump the 7-Zip version, update `scripts/7zip-versions.json` (URLs + SHA-256), update
   THIRD_PARTY_NOTICES.md, and re-run the full fixture suite on all 3 OSes.

## Sensitive areas (ask a human first)

`src/main/safety/**`, `src/main/engine/args.ts`, `build/installer.nsh` (registry writes), code-signing config.

## Testing expectations

- Every new format or option: add a fixture to `test/fixtures/` (generated by `scripts/make-fixtures.ts`) and a parser test.
- Every safety rule: a malicious fixture that proves the rule blocks it.
- UI flows: Playwright E2E through the real engine.
