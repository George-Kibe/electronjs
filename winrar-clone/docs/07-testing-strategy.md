## 1. Test pyramid

| Layer | Tooling | Scope | Runs |
| --- | --- | --- | --- |
| Unit: parsers | Vitest + captured output fixtures | `list`, `progress`, `errors` parsers, per OS × 7-Zip version | PR |
| Unit: safety | Vitest + fast-check property tests | Path validation, name sanitization, bomb math, symlink policy | PR |
| Unit: args | Vitest (snapshot of argv arrays) | Every request → exact 7-Zip argv. No shell strings. | PR |
| Unit: renderer | Vitest + Testing Library + vitest-axe | Components, table virtualization, dialogs | PR |
| Integration: engine | Vitest (node) + real bundled 7-Zip + fixture corpus | list/extract/test/create round trips, passwords, volumes, cancellation | PR (Linux) · nightly (3 OS) |
| Integration: jobs + safety | Same | Full pipeline incl. staging, post-validation, collisions, bomb aborts | PR (Linux) · nightly (3 OS) |
| E2E | Playwright `_electron` | User journeys through the UI; CLI/second-instance intents | PR smoke (Linux) · nightly (3 OS) |
| OS integration | Scripted per-OS jobs (PowerShell, bash) | Registry keys present after install and removed after uninstall; `.desktop` MIME; `open-file` | Nightly + release |
| Performance | Benchmark script | NFR-PERF-01..04 against raw 7-Zip | Nightly |

## 3. Fixture corpus

- Generated by `scripts/make-fixtures.ts` into `test/fixtures/` (gitignored). CI caches it, keyed by the
  script's hash.
  - Benign archives are created with the bundled 7-Zip (zip, 7z, tar.*), Python `zipfile`/`tarfile` (for
    crafted headers, links, device entries, lying sizes) and pre-built RAR samples.
- **RAR fixtures:** we cannot create RAR without WinRAR. A small set of RAR4/RAR5 samples (single,
  multi-volume, encrypted, encrypted headers, solid) is committed under `test/fixtures/rar/` with a README
  saying how they were made and their SHA-256. They are generated once by a maintainer with a licensed copy
  of WinRAR, or taken from public-domain test suites with compatible licenses.
- Malicious samples are built programmatically at test time. We never commit live malware. Executables in
  fixtures are harmless stubs (`echo` scripts / empty PE headers) that only look dangerous.

## 4. Test harness rules

- Each integration test runs in its own temp root, with a **canary** sibling directory. After the test, the
  harness asserts that the canary tree is byte-for-byte unchanged (proves nothing escaped).
- Tests run against the bundled 7-Zip binary, never a system-installed 7-Zip.
- E2E on Linux uses `xvfb-run`. Dialogs are stubbed through a test-only IPC hook, compiled out of production builds.

## 5. Coverage gates

`safety/` 95 % · `engine/` parsers and args 90 % · main overall 75 % · renderer 60 %. PRs fail below the gate.

## 6. Release QA checklist (each OS)

- [ ] Fresh install. File associations appear under "Open with". The context menu shows the configured items.
- [ ] Double-click `.rar`, `.zip`, `.7z` → browser opens
- [ ] Extract here / to / smart from the context menu with the app closed (headless window) and with it open
- [ ] Encrypted + multi-volume RAR5
- [ ] Create zip and 7z with a password + split. Open them in another tool to cross-check.
- [ ] Drag in and drag out
- [ ] Auto-update from the previous version
- [ ] Uninstall removes context menu entries and associations. User data is kept unless "remove data" was chosen.
- [ ] Screen reader smoke (NVDA / VoiceOver / Orca) on the browser table and job progress
